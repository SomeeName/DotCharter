# tools/chart-eval

Scores the AUTOMATIC chord fingering (`ChordTemplateFingerSetter`) and FHP generation
(`FretAnchorGenerationService`) against charts a human finished. `ChartEval.cs` is a .NET 10
file-based program over `DotCharter.Services`, so it always measures the code of the tree it
runs in — run it from a worktree to measure that worktree.

```powershell
dotnet run tools/chart-eval/ChartEval.cs -- --corpus <corpus.json> [--kind guitar|bass|all] `
    [--split train|holdout|all] [--fhp-fingers auto|reference] [--free-fingering suggested|none] [--song <substr>] `
    [--json <out.json>] [--baseline <old.json>] [--detail <out.tsv>] [--octaves <out.tsv>] `
    [--sounds <out.tsv>] [--fixture <out.json>] [--style prefix|halves|loto|oracle|none]
dotnet run tools/chart-eval/ChartEval.cs -- --corpus <corpus.json> --learn DotCharter.Core/Utilities/LearnedChordFingeringData.cs
dotnet run tools/chart-eval/ChartEval.cs -- --tabs <gp-dir> --gold <gold.tsv> [--detail <out.tsv>]
```

The program drops itself to idle priority on CPUs 8-15.

## Charts mode

Every RS-XML listed in the corpus is a finished, single-level chart. Its notes stay; its anchors
and chord fingerings are stripped and regenerated by the production code:

- **FHP** — for every fretted sound, does the generated anchor that governs it sit on the same
  fret as the charter's? Also counts anchor CHANGES over the fretted-sound sequence (generated
  vs reference): agreement must not be bought with an anchor per note.
- **Fingering** — for every chord whose template is fully fingered, the suggester's fingering
  from the frets alone vs the charter's. Exact per chord, per string, per distinct shape, and by
  shape class (fretted strings, barre in the reference).
- `--fhp-fingers auto` (default) feeds the anchor walk the SUGGESTED fingers, as a fresh chart
  would have. `reference` feeds it the charter's fingers, isolating the walk itself.
- `--free-fingering suggested` (default) runs the production pipeline: a chord whose
  fingering equals the suggestion is FREE, the walk may hold the hand for it and
  `ChordFingeringFollower` re-fingers it. `none` treats every fingering as authored. The extra
  column **after FHP** is the chord fingering exact rate AFTER that pass (the follower's variant
  where it re-fingered), next to how many chords it re-fingered; the context-free columns are
  unchanged.
- `--split`: one song in five is HELD OUT (stable SHA-1 of the song key). Tune on `train`, report
  `holdout` too; a gain that only shows on train is overfitting.
- **Octave starts** (bass) — a fretted single note followed within the next two notes by
  the same note two strings up and two frets higher (and SOUNDING an octave higher through the
  chart's tuning, so drop D's low string does not count), whose previous note was neither that
  root nor its octave. The `TOTAL bass … octave starts` line gives how often the anchor governing the
  root sits ON the root, for the reference and for the generated anchors. `--octaves <out.tsv>`
  dumps every start (and every octave-DOWN start) with its slide, gap and neighbouring anchors.
- `--split all` also prints one `SPLIT <split> <kind>` line each, with FHP and fingering to two
  decimals: one run instead of two when sweeping a constant. Always sweep with `--kind all`: one
  holdout chart is exported both as a guitar and as a bass part, and only `--kind all` drops the
  bass copy as a duplicate (`--kind bass` scores it, 0.4 pp lower).
- `--sounds <out.tsv>` dumps EVERY fretted sound: notes with techniques, the reference and
  generated anchor (and whether one starts there), the walk rule that emitted the generated one
  (`FretAnchorGenerationService.RuleTrace`, read by reflection), and for a chord the charter's,
  the suggested and the final fingering. It is how fingering levers are found and sized before any
  is built; it holds song content, so it stays owner-local.
- `--style` — the suggester follows the arrangement's own `1·3` / `1·4` for a power chord
  and a two-fret octave (`ArrangementFingeringStyle`), as the app does once a chart has fingered
  ones. A real chart only has the charter's OTHER answers, so a template's hint is never computed
  from its own reference fingering: `prefix` (default) takes the templates first played before it
  (charting from the start, the in-app flow); `halves` the templates first played in the other
  half of the arrangement; `loto` every other template (the rest already authored); `oracle` its
  own answer too (a ceiling, never a result); `none` no hint. The free-grip test of the walk gets
  the same hint the template was suggested with.
- The same arrangement exported twice is scored once (signature of its notes). DD charts
  (more than one level) are skipped: their hardest level is a fragment.

The corpus file is owner-local (`DotCharter-local/scratch/ChordEval/corpus.json`, built by
`build_corpus.py` there from the owner's list of charts he vouches for: 86 songs, 119 guitar and
71 bass arrangement XMLs). Never commit it or anything from it.

## Hand-shape suggestions

`HandShapeEval.cs` scores `HandShapeSuggester` on the same corpus and split:

```powershell
dotnet run tools/chart-eval/HandShapeEval.cs -- --corpus <corpus.json> [--split train|holdout|all] `
    [--kind guitar|bass|all] [--no-anchors] [--sweep] [--min-sounds n] [--min-strings n] `
    [--min-strings-alone n] [--max-spread n] [--max-gap beats] [--detail <out.tsv>] [--fixture <out.json>]
```

Each chart keeps its notes, chords, anchors and the templates its CHORDS use; its hand shapes and
the templates only bars use (the answer key) are stripped. **notes** scores every single note:
under a charter's bar and/or a proposal, precision TP/(TP+FP), recall TP/(TP+FN) — the headline.
**bars** counts a proposal matching a charter's bar over a single note at sound-Jaccard ≥ 0.5.
The run ends with the missed notes grouped by the first rule the charter's own bar breaks.
`--sweep` grids the limits; `--detail` dumps every proposal with its features (song content:
owner-local). `--fixture` writes `DotCharter.Tests/Services/Editing/HandShapes/Fixtures/hand-shape-suggestion-floor.json`
(24 train windows, relative positions, no names) for `HandShapeSuggesterCorpusFloorTests`.

Measured 2026-10-09 (guitar, defaults: ≥ 3 sounds, ≥ 4 strings or ≥ 3 inside a declared shape,
spread ≤ 3, gap ≤ 2 beats, one chord shape): **train notes P 74.6 % R 63.2 %** (6,193 / 2,114 /
3,603), bars P 64.4 % R 37.7 %; **held-out notes P 83.4 % R 51.2 %** (789 / 157 / 751), bars P
61.3 % R 23.6 %. Anchors stripped: train 71.0 / 63.4, held-out 70.0 / 52.3. Most misses are the
charters' bars over one or two sounds or two strings (a single sustained note, a double stop
with one picked note), which the issue's ≥ 3-note rule leaves alone on purpose; most extra
proposals are in parts whose charter barred no single note at all. Bass: 0 of 1,101 proposed
notes sat under a charter's bar, so bass gets no suggestions. Two-string grips were 11 % precise,
three-string grips with no containing template 20 %. Re-measure; never carry these forward.

## Generated files

- `--learn <file>` writes `DotCharter.Core/Utilities/LearnedChordFingeringData.cs`, the chord
  shapes the charters finger differently from `ChordTemplateFingerSetter`'s heuristic. TRAIN split
  only, whatever `--split` says; aggregated counts only. Regenerate it after a corpus or heuristic
  change and re-measure.
- `--fixture <file>` writes `DotCharter.Tests/Services/Editing/FretAnchors/Fixtures/chart-style-floor.json`,
  the windows `ChartStyleFloorTests` scores in the default gate (24 × 48 struck positions per
  instrument; ordinal positions, no song names). Regenerate it with the floors when a change
  legitimately moves them.

## Gold mode

Imports Guitar Pro tabs through the real `GpImporter` (which generates anchors and fingers) and
scores them against a hand-written key. The TSV format is documented on `GoldMode` in
`ChartEval.cs`; rows match by file, track, position (ms on the tab's own tempo map, ±3 ms) and
the set of notes.

## AI pass (`AiChartEval.cs`)

Runs the AI chart pass (`DotCharter.Services/Ai/Chart/`) on corpus arrangements through a REAL
provider and scores it next to the algorithm it starts from: the same "auto" state as above
(suggested fingers, the walk with free grips, the follower's variants), so the algorithm column
equals `ChartEval.cs --split holdout` per arrangement. `--job` picks the mode: `joint` (FHP +
fingering), `fhp` (FHP only; free fingerings follow through `ChordFingeringFollower`) or
`fingering` (fingering only; anchors fixed). It spends the user's model usage — keep the selection
small and held-out; `--allow-train` is for tuning runs.

```powershell
dotnet run tools/chart-eval/AiChartEval.cs -- --corpus <corpus.json> --list
dotnet run tools/chart-eval/AiChartEval.cs -- --corpus <corpus.json> --pick "<song>|<xml file>" [--pick ...] `
    [--job joint|fhp|fingering] [--model claude-sonnet-5-5] [--provider claudecli|codexcli] [--concurrency 3] `
    [--until-sound N] [--out <dir>]
```

`--out` gets per-arrangement numbers and rejection reasons, never a prompt or a reply.
